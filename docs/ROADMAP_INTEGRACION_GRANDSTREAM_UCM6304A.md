# Roadmap de integracion Grandstream UCM6304A con SIRICO

Documento vivo para avanzar por checkpoints, registrar hallazgos y ajustar el rumbo sin perder contexto.

## Decisiones base

- Ambiente inicial: local/red interna.
- Produccion actual: Bluehost.
- Conectividad recomendada por ahora: agente local en la red donde esta el UCM.
- Fuente de verdad de extensiones: Grandstream UCM.
- SIRICO solo relaciona extensiones con usuarios existentes.
- No iniciar con AMI, CTI, tiempo real, grabaciones, click-to-call ni automatizaciones.
- No usar `HTTPS API Settings (Old)` como base de desarrollo.
- No inventar endpoints ni campos: se confirman con respuestas reales del equipo.

## Nota sobre API HTTP, agente local y produccion

La pregunta clave no es solo si el UCM tiene API HTTP, sino desde donde se puede consultar.

Si SIRICO corre en Bluehost y el UCM esta dentro de la oficina, Bluehost normalmente no puede ver una IP local como `192.168.x.x`. Aunque la API exista y funcione en la red local, produccion no podria consultarla directamente sin abrir puertos, VPN, tunel o un proceso local.

Por eso el enfoque recomendado es:

1. Un agente local corre dentro de la red de oficina.
2. El agente consulta el UCM por red local.
3. El agente envia a SIRICO solo datos normalizados o lotes de CDR.
4. SIRICO guarda, relaciona y muestra la informacion.

Esto evita exponer el UCM a Internet y permite validar primero en local.
